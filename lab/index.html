Engineering Lab

My engineering lab is a small self-hosted platform for networking, home automation, personal services, media, documents, AI tooling, monitoring and recovery practice. The current platform uses Proxmox for the network and appliance layer, a dedicated Docker service host for application stacks, Git-backed configuration, Komodo for deployment, and Backrest/Restic backups with restore drills.

Why it exists

A place to build outside production.

A place where I experiment with infrastructure, privacy, open-source software, automation, networking, self-hosting, and autonomous agents outside the constraints of production systems.

At a glance

The current lab in one table.

Network and appliance layer
A Proxmox host running OPNsense and Home Assistant OS, with the firewall sitting between the network bridges
Service host
A dedicated Docker host for application stacks, dashboards, monitoring, organizer tools, media, photos, analytics and AI services
Deployment model
Docker Compose stacks managed from Git through Komodo, with stale manual stack copies archived after reconciliation
Observability
Homepage, Uptime Kuma, update checks, speed tests and small custom widgets for operational context
Recovery
Backrest and Restic cover the application state; a Vaultwarden restore drill verified files, database integrity and representative table counts
AI access
Hermes and OpenClaw agents reachable over Telegram, with supporting model routing and workflow services on the lab platform
How it fits together

Proxmox: one mini PC, three virtual machines.

Mini PC

Proxmox VE · hypervisor

OPNsenseVirtual machineDocker HostVirtual machineHome Assistant OSVirtual machine

Each physical Ethernet port has its own Linux bridge in Proxmox, and the virtual machines plug into the bridges rather than into the ports. OPNsense is the only guest on both bridges, so it sits between the two networks and all traffic between them has to pass through it. Every guest starts on its own after a power cut, so the lab comes back without anything to do by hand.

What runs where

The lab is now split by responsibility.

OPNsense. The firewall and router, running OPNsense 26.7 in a virtual machine with 4 virtual CPUs and 2 GiB of memory. It sits between the two Ethernet ports. Its page has step-by-step guides for static IP mappings, a WireGuard VPN, Unbound ad blocking, and a Caddy reverse proxy.

Dedicated service host. The application platform now runs on a dedicated Docker host with Compose stacks grouped by purpose: infrastructure, organizer tools, analytics, AI tooling, backups, media and photos. Stack definitions are reconciled into Git and deployed through Komodo. The dashboard is also the subject of a case study on configuring it with AI.

Service host migration. The migration moved the active self-hosted platform off the constrained Docker VM, retired a stale duplicate analytics stack, reconciled live definitions into Git and proved recovery with a Vaultwarden restore drill.

Home Assistant OS. Home Assistant OS 13.1 in a virtual machine with 2 virtual CPUs and 4 GiB of memory. It needs UEFI firmware, so its virtual machine is built a little differently from the other two, and one USB device on the host is passed through to it.

Second mini PC

A dedicated machine for agents.

A dedicated machine hosts my AI agents and supporting services, including model routing, workflow automation, agent memory and web UI tooling. Hermes and OpenClaw are connected to Telegram, so I can message them and receive updates from my phone while keeping the operational pieces on infrastructure I control.

Limits

Where I draw the public/private line.

The public version of the lab intentionally avoids hostnames, addresses, private routes, credential paths and exact service endpoints. The interesting part is the operating model: services are grouped by purpose, configuration is kept in Git, the deployment control plane is reconciled with the live containers, and backups are tested with restore drills instead of assumed from green job output.
